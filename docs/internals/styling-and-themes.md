# Styling & Theme Architecture

This document describes faah's styling architecture, CSS custom property design system, dynamic theme loading pipeline, and token specifications.

faah reads every colour in the user interface through a CSS custom property, known as a token. A theme is defined in a single CSS file that assigns values to these tokens.

## 1. How Themes Load

- `web/app.css`: Generated by Tailwind from `web/tailwind.css`, which imports Tailwind, Basecoat Vega, then `style.css`, `workbench.css` and `desktop.css` in the components layer. Build inputs stay in the checkout; only `app.css` is embedded.
- `web/style.css`: Holds layout, grid geometry, and component styling. It contains no literal colors. Its `:root` block defines structural typography tokens (fonts, sizes) and provides fallbacks for optional colour tokens.
- `web/themes/<id>.css`: Each theme resides in its own file under [`web/themes/`](../../web/themes/), containing a single rule for `:root[data-theme="<id>"]`. The filename without extension acts as the theme ID.
- Dynamic Concatenation (`/static/themes.css`): The Go server concatenates every file matching `web/themes/*.css` in alphanumeric order once (`sync.Once`) and serves the cached stylesheet at `/static/themes.css`. [`web/index.html`](../../web/index.html) links this unlayered file immediately after `app.css`.
- Client-Side Discovery: At application boot, [`web/src/theme.js`](../../web/src/theme.js) scans the loaded document stylesheets for rules matching `:root[data-theme="<id>"]`. It extracts the human-readable display name from `--theme-name` and the color scheme hint from `color-scheme`.
- State Persistence: The active theme is applied via the `data-theme` attribute on the `<html>` root element and paired with the `dark` class for dark schemes and persisted in `localStorage` under `faah.theme`. If a saved theme is removed, faah falls back to the default `catppuccin-mocha`.

> [!NOTE]
> Theme rules intentionally use `:root[data-theme="<id>"]` rather than a bare attribute selector `[data-theme="<id>"]`. Themes load unlayered after `app.css` so their tokens override Basecoat defaults. The `:root` specificity also keeps them above component fallbacks.

The explorer header controls use the same tokenized `.mini` button style as Re-index. The Expand All progress state uses accent tokens; its pulse runs only when the browser allows motion, and keyboard focus uses a visible tokenized outline.

## 3. Creating a Custom Theme

1. Copy an existing theme file:
  ```bash
  cp web/themes/dark.css web/themes/midnight.css
  ```
1. Update the selector to match the new ID:
  ```css
  :root[data-theme="midnight"] {
  ```
1. Set the metadata properties:
  ```css
  --theme-name: "Midnight";
  color-scheme: dark;
  ```
1. Define the required color tokens (see Token Reference below).
1. Install the root build dependencies and generate the stylesheet and scripts:
  ```bash
  npm ci
  node scripts/build-web.js
  ```
1. Preview by running faah with `go run .` (rebuild after each CSS change; themes are embedded):
  ```bash
  go run . .
  ```
1. Run unit tests to verify theme conformance:
  ```bash
  go test ./...
  ```
  `TestThemesStylesheetJoinsEveryThemeFile` in [`px0_test.go`](../../px0_test.go) ensures all required tokens are present and selector IDs match filenames.

## 4. Complete Token Reference
### Surface Elevation Tokens

Four progressive elevation steps radiating from the editor viewport outward:

| Token  | Required | Controls                                                                                                                |
| ------ | -------- | ----------------------------------------------------------------------------------------------------------------------- |
| `--background` | Yes      | Editor background, line gutter, active tab, text inputs, hovercard signature block, Markdown preview background.        |
| `--sidebar`, `--card`| Yes      | File explorer sidebar, tab bar, right inspector, status bar, hovercard action row, Markdown code blocks and table headers.|
| `--popover`, `--secondary`, `--muted`| Yes      | Floating surfaces (hovercard, findbar, command palette, shortcut cheatsheet, toast), row hover state, keycaps, badge fills.|
| `--accent`| Yes      | Small button hovers (close tab, status bar icons), active status buttons, double-click occurrence highlight, scrollbar thumb.|

### Text & Contrast Tokens

| Token              | Required | Fallback      | Controls                                                                                                              |
| ------------------ | -------- | ------------- | --------------------------------------------------------------------------------------------------------------------- |
| `--foreground`             | Yes      | -             | Primary text, active file tab, current line number, unstyled identifiers.                                             |
| `--muted-foreground`            | Yes      | -             | Secondary text: inactive tabs, explorer file names, hovercard docs, Markdown blockquotes and footnotes.              |
| `--faint`          | Yes      | -             | Line numbers, keyboard hints, tree chevrons, close buttons at rest, inactive LSP indicator.                         |
| `--primary-foreground`      | Yes      | -             | Text rendered on top of an `--primary` background.                                                                     |
| `--on-badge`       | No       | `var(--background)`   | Text rendered inside colored badges (symbol kinds, file extensions).                                                  |
| `--on-mark-active` | No       | `var(--background)`   | Text of current search/find hit on top of `--mark-active`.                                                             |

### Borders, Accents & Selection

| Token            | Required | Controls                                                                                                |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------- |
| `--border`         | Yes      | Dividers, pane borders, occurrence outlines, Markdown table borders, code block borders.                |
| `--primary`       | Yes      | Active tab top indicator, input focus borders, resizer drag handle, Ctrl+hover link underlines, button hovers.|
| `--primary-text`    | Yes      | Accent-colored text: active inspector tab, palette match characters, Markdown links, status button hovers.|
| `--sel`          | Yes      | Selected tree row, palette row, native text selection, whole-file selection (Ctrl+A).                   |
| `--mark`         | Yes      | Background of search and find matches.                                                                  |
| `--mark-active`  | Yes      | Active find match, minimap match indicators, pulsing LSP status dot.                                   |
| `--cur`          | Yes      | Active line background and current gutter cell highlight.                                               |
| `--shadow`       | Yes      | Elevation box-shadow for floating overlays (palette, hovercard, findbar).                                |

The paired surface tokens keep the same palette value: `--card` uses the sidebar value; `--popover`, `--secondary`, `--muted` and `--sidebar-accent` share the raised surface value. All `*-foreground` surface tokens use `--foreground`. `--input` and `--sidebar-border` share `--border`; `--ring`, `--sidebar-ring` and `--sidebar-primary` share `--primary`. `--sidebar-primary-foreground` shares `--primary-foreground` (required in every theme). `--destructive` is the UI error colour; `--err` remains the syntax error colour. Desktop focus shadows use `--focus-shadow`, while `--ring` is a colour.

### Syntax Highlighting Tokens

Generated by Chroma and formatted using short CSS classes ([`internal/render/render.go`](../../internal/render/render.go)):

| Token   | Class  | Semantic Role                           | Required | Fallback   |
| ------- | ------ | --------------------------------------- | -------- | ---------- |
| `--k`   | `.k`   | Keywords (`func`, `return`, `class`)    | Yes      | -          |
| `--kt`  | `.kt`  | Primitive types (`int`, `string`, `bool`)| No      | `var(--k)` |
| `--nf`  | `.nf`  | Function names and method calls         | Yes      | -          |
| `--nc`  | `.nc`  | Classes, structs, interfaces            | No       | `var(--nf)`|
| `--nb`  | `.nb`  | Built-in functions and standard types   | No       | `var(--nf)`|
| `--nv`  | `.nv`  | Variables and parameters                | No       | `var(--foreground)`|
| `--no`  | `.no`  | Constants                               | No       | `var(--m)` |
| `--s`   | `.s`   | String literals and characters          | Yes      | -          |
| `--m`   | `.m`   | Numeric literals                        | Yes      | -          |
| `--o`   | `.o`   | Operators (`+`, `-`, `*`, `&&`)         | No       | `var(--foreground)`|
| `--p`   | `.p`   | Punctuation (braces, parentheses, commas)| No      | `var(--muted-foreground)`|
| `--c`   | `.c`   | Comments (italicized)                   | Yes      | -          |
| `--err` | `.err` | Syntax errors (wavy underline)          | Yes      | -          |
| `--gi`  | `.gi`  | Git added lines, ready LSP dot          | No       | `var(--s)` |
| `--gd`  | `.gd`  | Git deleted lines, failed LSP dot       | No       | `var(--err)`|

## 5. Table Preview Styling

CSV and TSV tabs render inside `#mdview` with the article's class switched from `md` to `csv`, so no `.md` rule reaches the table. Every rule is scoped under `#md.csv` / `.csv-t` in [`web/style.css`](../../web/style.css) and takes its colours from the tokens above, which is why no theme needs table-specific values:

| Element | Tokens |
| --- | --- |
| Header row (sticky `th`) | `--sidebar` background, `--border` rule |
| Alternate rows | `--cur` |
| Column dividers, gutter edge | `--border` (inset box-shadows, so sticky cells keep their borders) |
| Line-number gutter (sticky) | `--faint` text on `--background` |
| Missing cells | hatched `--muted` |
| Find matches | `--mark`, `--mark-active` / `--on-mark-active` |
| Row-cap footer | `--muted-foreground` text, `--primary-text` button |

## 6. Mermaid Diagram Styling

Mermaid fences render inside `.md-mermaid`, a tokenized, scrollable surface using `--sidebar`, `--muted`, `--accent`, `--border`, and `--destructive`; generated SVG is constrained to the article width. Each diagram's controls toolbar provides zoom in/out, fit, and full-screen maximize using those same tokens, scaling only its `.md-mermaid-canvas`. In full-screen mode (`.md-mermaid.is-fullscreen`), the surface takes over the full viewport using `--background`, locks `document.body` scroll via `.mermaid-fs-active`, pins the controls to the top-left, and provides dedicated close buttons (`.md-mermaid-fs-close` in the top-right corner and `.md-mermaid-fs-only` in the toolbar) for easy zoom and `Esc` dismissal. Mermaid itself receives a `base` theme derived from the active faah theme's `--background`, `--sidebar`, `--muted`, `--foreground`, `--muted-foreground`, and `--border` values. `setTheme` emits `theme:changed`, and the Markdown preview debounces a rerender of the active diagrams so both palette previews and persisted theme changes remain readable.

Repository-supplied SVG is still removed by the Markdown sanitizer. Only SVG generated after sanitization by the pinned, strict-mode Mermaid runtime reaches `.md-mermaid`.
