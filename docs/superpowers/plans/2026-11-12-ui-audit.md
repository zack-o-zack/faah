## Detailed Findings by Severity

### P1-1 — Dense actions fall below the minimum target size

- **Location:** web/index.html:20, :610; web/src/tree.js:51, :70; web/src/tabs.js:547; web/src/vim.js:94.
- **Category:** Accessibility / Responsive.
- **Impact:** Explorer actions are 20×20; tab closes 16×16; tree menus 14×14; stage checkboxes 13×13; status actions 20px high. Adjacent explorer buttons and stacked tree actions do not meet spacing exceptions. Misclicks are especially costly around staging and closing tabs.
- **Standard:** WCAG 2.5.8, Target Size (Minimum). Inline code line actions have keyboard/selection equivalents and essential line-height constraints; they require a separate contextual assessment, not a blanket row-height increase. Native checkbox styling alone is not a finding; tiny explicitly authored sizing and adjacent target spacing are.
- **Fix:** Remove legacy size/padding/font overrides from shared buttons, use Basecoat sizes, and give staging a 24px label target while retaining the native checkbox appearance. Preserve dense code geometry.
- **Suggested command:** /impeccable adapt.

### P1-2 — Theme tokens make meaningful text and input boundaries too faint

- **Location:** web/themes/{catppuccin-mocha,light,dracula,solarized-light}.css; web/workbench.html:80.
- **Category:** Theming / Accessibility.
- **Impact:** Line numbers, tertiary text, syntax comments, accent text and Solarized button text are difficult to read. Input boundaries blend into their background. Hover and selected surfaces reduce contrast further.
- **Standard:** WCAG 1.4.3 and 1.4.11. Structural dividers need not all reach 3:1; input boundaries that identify a control do.
- **Fix:** Correct foreground, muted/faint, syntax, accent and input tokens in theme files. Validate against the actual surfaces, including hover/selected fills. Avoid globally darkening decorative borders.
- **Suggested command:** /impeccable colorize.

### P1-3 — Custom selectable rows omit keyboard operation

- **Location:** web/src/reviewflow.js:389; web/src/tabs.js:539; web/src/tree.js:55, :71; web/src/shortcuts.js:115.
- **Category:** Accessibility / Implementation Integrity.
- **Impact:** Review stages and file/tab rows are clickable divs without a reachable selection control. Tree menus explicitly have tabindex=-1. Global editor navigation can capture arrows while toolbar controls have focus.
- **Standard:** WCAG 2.1.1, 2.4.7, 4.1.2.
- **Fix:** Use native buttons for stage/tab selection, focusable file rows with scoped keyboard activation, reachable tree menus, and keep unmodified navigation keys with the focused control. Keep existing editor shortcuts.
- **Suggested command:** /impeccable harden.

### P1-4 — Input names rely on placeholders or nearby text

- **Location:** web/index.html:226, :295, :462, :481, :932, :952; web/src/tips.js (tips-filter).
- **Category:** Accessibility.
- **Impact:** The code editor, search/filter fields, stage editor, follow-up composer and JSON settings editor lack programmatic names in rendered checks. The placeholder disappears during use.
- **Standard:** WCAG 1.3.1 and 4.1.2.
- **Fix:** Associate existing visible labels, or supply concise aria-labels where surrounding UI provides the visible context. Do not duplicate verbose help as a field name.
- **Suggested command:** /impeccable clarify.

### P2-1 — Two Source buttons describe different axes

- **Location:** web/index.html:158–166; web/src/status.js:34–75.
- **Category:** Implementation Integrity / Usability.
- **Impact:** “Preview / Source / Source / Diff” forces users to infer whether Source exits a rendered preview or exits a diff.
- **Standard:** Nielsen consistency and match with the user's task.
- **Fix:** Keep Preview/Source as the format choice; call the other axis File/Changes and name both groups accurately. Hide the irrelevant format choice during a diff.
- **Suggested command:** /impeccable clarify.

### P2-2 — Copy code competes with the language label and code

- **Location:** web/src/markdown.js:270–283; web/tailwind.css:238–251.
- **Category:** Implementation Integrity / Responsive.
- **Impact:** Top-right absolute copy button and generated language label share coordinates; long first lines pass underneath. The icon looks broken and can hide code.
- **Fix:** Reserve a real toolbar row for the language and copy action, keep preformatted code scrolling independently, and preserve the data-control copy hook and Mermaid behavior.
- **Suggested command:** /impeccable layout.

### P2-3 — README theme-aware image sources are discarded

- **Location:** web/src/markdown.js:145–150, :170–209; README.md:1–5.
- **Category:** Theming.
- **Impact:** The white fallback logo is faint in light themes because picture is unwrapped and source is dropped. Browser prefers-color-scheme would also disagree with a forced app theme.
- **Fix:** Support only safe picture image sources: validated/resolved single-image srcset URLs, known color-scheme media values and no event/style attributes. Select by the app theme and resynchronize on theme changes. Preserve fallback alt text and reject unsafe URLs.
- **Suggested command:** /impeccable harden.

### P2-4 — Workbench current-folder action clips its leading text

- **Location:** web/workbench.html:77–82; web/src/workbench.js:264–268.
- **Category:** Responsive / Usability.
- **Impact:** A flex-centered button with overflow truncation clips “Open” and the path's beginning inside Recent. The destination cannot be identified reliably.
- **Fix:** Separate a stable Open label from a shrinking path span; allow the card header to wrap, and retain the full destination in its accessible name/title.
- **Suggested command:** /impeccable layout.

### P2-5 — Review card actions form an inconsistent vertical column

- **Location:** web/src/reviewflow.js:390–405.
- **Category:** Implementation Integrity / Usability.
- **Impact:** Pending status, edit and delete stack beside an already cramped title. Cards become tall and the title can disappear into truncation in the narrow stage list.
- **Fix:** Give stage selection a full-width text area, group edit/remove horizontally, and keep status consistently aligned. Use a real selection control and wrapping title/question.
- **Suggested command:** /impeccable polish.

### P2-6 — Documentation hover needs a bounded, keyboard-accessible path

- **Location:** web/index.html:291; web/src/hover.js:75–170; web/src/cardkeep.js:104–138.
- **Category:** Accessibility / Responsive.
- **Impact:** The hover card is limited to 580px rather than its editor host. Narrow hosts can clip its actions. It opens by pointer only, and focus-in cancels a timer without keeping it open on subsequent pointer movement.
- **Standard:** WCAG 1.4.13 and 2.1.1; equivalent definition/reference commands cover many actions, but not reading documentation.
- **Fix:** Bound width/height to the host, offer a command/shortcut for documentation at the caret, focus the keyboard-opened card, and keep it open while focus remains inside. Preserve Escape and pointer travel behavior.
- **Suggested command:** /impeccable harden.

### P2-7 — Startup tips cover active editing/review controls

- **Location:** web/src/tips.js:338–358.
- **Category:** Usability / Implementation Integrity.
- **Impact:** A timed floating tip can cover the stage editor's Cancel action at 1000×700. Prior capture failure is reproducible from its pointer interception log. Automatically teaching over active work interrupts the review task.
- **Fix:** Limit the startup popup to the welcome state; keep manual tips, the inspector list and the existing preference available.
- **Suggested command:** /impeccable distill.

### P3-1 — Native and assistive-technology verification remains

- **Location:** Desktop shell and overall UI.
- **Category:** Accessibility / Responsive.
- **Impact:** Browser emulation cannot establish real titlebar hit regions, operating-system tooltips, screen-reader announcements or touch behavior.
- **Fix:** Owner/device verification before claiming full native or WCAG conformance; no speculative implementation change.
- **Suggested command:** /impeccable audit.

## Usability critique

Operate mode: a developer needs to locate a change, understand it, stage it, and verify it without losing context. Existing explorer/editor/inspector regions, recent commits, tab history and keyboard palettes support that loop. Preview/diff labels and pointer-only selections undermine the same loop at precisely the moments where users switch context.
